# 操作型 Skill 审计

## 目标与输入

- 解决：Skill 看起来有风格、有知识，却不能稳定完成任务或守住边界。
- 输入：Skill 的 `SKILL.md`、引用的脚本/模板/资料、预期触发场景、至少一个真实任务。
- 输出：五维评分、阻断问题、证据化修改建议、触发与执行抽测结论。

## 来源与方法骨架

- 来源：视频 12:07–12:58，辅以 03:19–03:50 和 13:43–14:43。
- 短证据：好 Skill 要把“隐性的知识显性化”，并定义“边界”“工具”“好坏标准”和“context”；真正的 Skill 与“流程、工具、标准”有关。
- 解释：人格和风格最多改变表达，不能替代任务程序。操作型 Skill 必须让另一个 agent 知道何时触发、按什么顺序行动、能用什么、怎样验收、何时停止，以及执行所需的最小背景。
- 置信度：高。来源明确列出质量构成；评分阈值是本包为可执行审计所作的操作化设计。

## 何时使用

- 安装、发布或分享一个 Skill 前进行质量门审查。
- Skill 经常输出漂亮文字，但实际任务完成不稳定。
- 需要区分“角色/风格 prompt”和“操作能力”。
- 用户信号：“审计这个 skill”“看看边界写清楚没有”“它为什么总跑偏”“is this operational or just a persona?”。

## 执行

1. 明确承诺与真实任务
   - 提取 Skill 声称解决的问题、触发信号、不适用场景和交付物。
   - 选一个典型任务、一个诱饵任务和一个高风险边界任务。
   - 产物：审计基线。
   - 完成标准：能用可观察行为描述“成功”，而不是“像某专家”。
2. 五维逐项取证
   - **流程**：是否有动作顺序、步骤产物和判停条件。
   - **工具**：是否说明需要什么工具、权限、失败回退和不可执行项。
   - **标准**：是否定义好坏、完整性、准确性或验收门槛。
   - **边界**：是否说明不适用场景、风险、拒绝或升级条件。
   - **上下文**：是否定义所需输入、来源、选择规则与隐私最小化。
   - 每维按 0=缺失、1=提到但不可执行、2=可执行且可验证评分，并引用具体位置。
   - 产物：0–10 分证据表。
3. 检查触发描述
   - 核对能力、应触发信号和不应触发邻近场景是否都写进 description。
   - 产物：触发缺口清单。
   - 完成标准：三个问题都有文本证据；没有只靠 Skill 名称猜测。
4. 识别阻断缺陷
   - 任一五维得 0；没有不应触发场景；需要危险权限却无确认；声称结果却无验收标准，均为阻断项。
   - 产物：按优先级排列的问题。
   - 判停条件：发现凭据外传、隐藏执行、破坏性默认动作或越权指令时，停止运行并转安全审计。
5. 做最小压力测试
   - 测典型正例、相邻诱饵和边界任务；检查是否选中、是否守边界、是否按步骤交付。
   - 产物：测试记录。
   - 完成标准：诱饵全部通过，总通过率至少 80%；否则不得判为可发布。
6. 给出可定位修订
   - 每条建议写明修改位置、缺失机制和修改后的可验证行为。
   - 结论：可发布 / 修改后复测 / 拒绝运行。
   - 完成标准：结论能由评分、阻断项和测试结果共同支持。

## 边界与失败模式

- 不用于：从零把长内容蒸馏为一组 Skills；这种任务应使用专门的内容蒸馏流程。
- 不用于：恶意代码、依赖供应链、凭据读取等深度安全审计；发现相关信号时转安全流程。
- 失败信号：把文采当质量；只数章节不验证动作；没有真实任务抽测；为了高分降低诱饵难度。
- 方法局限：五维来自视频，具体 0–2 评分和发布门槛是为审计可重复性添加的规则。
