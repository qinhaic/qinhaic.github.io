# Agent 工作流复利化

## 目标与输入

- 解决：AI 每次从零开始、只给建议不落地、产物无法进入下一轮的问题。
- 输入：一个真实且会重复出现的任务、当前步骤、所需资料、可用工具、目标产物和权限边界。
- 输出：一条可运行的 agent 工作流、持久资产清单、首次小规模运行结果和复用规则。

## 来源与方法骨架

- 来源：视频 01:55–03:50、04:44–06:56、11:00–12:05、20:35–21:08、25:07–25:51。
- 短证据：“上下文”“产出”“工具”能够积累，才可能产生复利；“学 AI 是在学动词”。
- 解释：聊天模式把人固定在逐轮传话的位置；agent 工作流把任务放进一个持久环境，让 AI 能读取必要材料、采取动作、把结果写回工作区，并把成功做法沉淀给下一次。
- 置信度：高。观点在原则、对比和多个真实工作流案例中重复出现；具体效率倍数没有作为方法承诺。

## 何时使用

- 同类任务每周或每月重复，仍需反复解释背景。
- AI 给出的结果还要人工搬到文档、表格、邮件或发布系统。
- 希望用 Codex、Claude Code、Cursor、Manus 等完成多步任务，而不只获得答案。
- 用户信号：“把这套流程交给 agent”“以后别从零开始”“让每次产出都能复用”“I want an agentic workflow”。

## 执行

1. 选择一个可控的真实任务
   - 记录触发条件、当前步骤、频率、人工耗时、失败代价和最终产物。
   - 优先选择重复、高摩擦、结果可验收且失败可恢复的任务。
   - 产物：一页任务卡。
   - 完成标准：能明确说出“何时开始、怎样算完成、失败会造成什么”。
   - 判停条件：任务涉及不可逆外部写入、资金、法律承诺或敏感数据，却没有明确授权与复核点。
2. 判断是否值得从聊天迁移
   - 检查四个信号：需要持久上下文、需要调用工具、需要保存产物、会重复运行。
   - 0–1 个信号：保留普通聊天；2 个信号：可试验；3–4 个信号：优先迁移。
   - 产物：迁移判断及理由。
   - 完成标准：没有把“agent 更先进”当作唯一理由。
3. 搭建最小脚手架
   - 只提供当前任务必要的资料、工具、偏好、质量标准和权限。
   - 为输入和输出指定稳定位置；明确哪些动作只读、哪些动作需用户确认。
   - 产物：脚手架清单与权限表。
   - 完成标准：agent 能在不反复询问稳定事实的情况下开始工作。
4. 围绕 agent 重画流程
   - 删除纯人工搬运步骤；把研究、生成、校验、保存和交付串成连续动作。
   - 在高风险或主观判断节点保留人工复核。
   - 产物：新版流程和人工检查点。
   - 完成标准：每一步都有输入、动作、输出和负责人。
5. 让第一次运行留下资产
   - 保存可复用的模板、检查清单、资料索引、决策标准和经过验证的中间产物。
   - 不把临时事实、秘密或整段无筛选聊天默认永久保存。
   - 产物：资产清单及下次使用条件。
   - 完成标准：至少一项资产能在下一次任务中直接减少重复劳动。
6. 用同类任务回放
   - 运行第二个相似任务，对比重新解释次数、人工搬运步骤、错误和交付时间。
   - 只根据实际失败补脚手架，不提前堆满复杂自动化。
   - 产物：回放记录和一项优先改进。
   - 完成标准：工作流能产出合格结果，或明确证明当前任务不适合 agent 化。

## 边界与失败模式

- 不用于：一次性解释、低风险头脑风暴、陪伴式对话，或无需工具和持久产物的简单请求。
- 失败信号：为了自动化而增加更多维护；所有上下文都无差别加载；没有权限边界；产物不经校验直接外发；只把旧步骤逐字自动化而没有重构。
- 方法局限：视频案例偏技术和内容生产；效率收益需在具体工作流中测量。
- 遇到“资料很多但不知道该给哪些”时，组合 `context-capital-routing`。
- 需要把成熟流程固化成 Skill 时，可使用现有 Skill 创建流程，并用 `operational-skill-audit` 审查。

## 关系

- depends-on：无。
- contrasts-with：普通一次性聊天。
- composes-with：`context-capital-routing`、`operational-skill-audit`。

## 使用后反馈

完成后可询问：这次最有用、最不准确或最希望下次改变的地方是什么？
未经用户授权，不根据单次反馈静默修改本 Skill。
