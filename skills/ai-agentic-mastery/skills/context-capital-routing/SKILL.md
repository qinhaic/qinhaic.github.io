# 上下文资本路由

## 目标与输入

- 解决：有大量历史资料，却无法让 AI 在正确任务中获得正确背景。
- 输入：资料来源、任务类型、稳定偏好、案例、质量标准、已有流程、隐私与保留规则。
- 输出：上下文资产目录、提炼后的资产卡、任务—上下文路由表、维护与删除规则、检索测试结果。

## 来源与方法骨架

- 来源：视频 03:19–03:50、05:52–06:43、12:07–12:58、13:43–15:05。
- 短证据：“先积累上下文”和“把上下文提炼好”是两个步骤；AI 需要知道“做什么任务需要什么上下文”。
- 解释：积累解决“没有材料”，提炼解决“材料不可用”，路由解决“给错或给多”。三者不能互相替代。模型和工具相似时，经过验证的案例、标准、偏好和流程会成为可复用差异。
- 置信度：高。视频明确区分积累与提炼，并给出个人和企业培训的复用案例。

## 何时使用

- 每次任务都要重新解释组织、项目或个人偏好。
- 文档很多，但 AI 不是遗漏关键事实，就是被无关历史干扰。
- 想建立团队知识、个人记忆或长期 agent 工作区。
- 用户信号：“上下文怎么沉淀”“哪些资料该自动加载”“做一个 context router”“让历史产物真正复用”。

## 执行

1. 先定义任务族
   - 列出 3–10 类高频任务及每类的合格输出。
   - 产物：任务族表。
   - 完成标准：任务类别由实际用途定义，不以文件夹名称代替。
2. 盘点并分级来源
   - 标记每项来源的所有者、更新日期、可靠性、敏感度和保留期限。
   - 分为：稳定事实、偏好、案例、标准、流程、历史产物、临时状态。
   - 产物：来源清单。
   - 完成标准：秘密、个人敏感信息和过期状态有明确排除或最小化规则。
3. 积累与提炼分开进行
   - 原始区允许低摩擦收集；资产区只放经过整理和去重的内容。
   - 每张资产卡写明：内容、证据来源、适用任务、更新时间、失效条件。
   - 产物：资产卡集合。
   - 完成标准：任何资产都能追溯来源，并知道何时不再可信。
4. 建立最小充分路由
   - 为每个任务族指定“必需、条件性、禁止”上下文。
   - 先加载稳定且高相关内容；只有任务信号满足时再加载条件性材料。
   - 产物：任务—上下文路由表。
   - 完成标准：每个选择规则都能回答“为什么这个任务需要它”。
5. 用对照任务测试
   - 选择至少两个不同任务：测试是否取到关键上下文、是否混入无关材料、是否引用过期内容。
   - 产物：检索测试记录。
   - 完成标准：关键上下文召回，无关或敏感上下文未误载；失败项进入修订清单。
6. 设置维护回路
   - 定义新增、更新、合并、失效和删除规则；重要资产指定复核频率。
   - 产物：维护协议。
   - 完成标准：系统不仅会增加内容，也会纠错和遗忘。

## 边界与失败模式

- 不用于：仅摘要一份文档、临时会议问答或无需跨任务复用的资料。
- 失败信号：把所有聊天永久保存；每个任务加载全部资料；没有来源和更新时间；为了“记忆”而扩大敏感数据暴露；只积累不删除。
- 方法局限：视频强调上下文的重要性，但没有给出具体数据结构；本 Skill 的资产卡和路由表是对其机制的操作化推演。
- 若主要问题是把整个任务从聊天迁到可行动环境，先用 `agentic-workflow-compounding`。
